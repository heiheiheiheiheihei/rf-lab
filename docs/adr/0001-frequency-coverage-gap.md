# ADR-0001:119–1050MHz 扫频需求与现有模块的覆盖空白

- 状态:`proposed`(待用户决策)
- 日期:2026-09-20
- 决策者:用户(产品所有者)
- 影响面:硬件选型、BOM、协议契约 `CAPS.bands`、App 扫频 UI

---

## 1. 背景与问题

产品需求 F-01 写明:

> 自动扫频:在 **119–1050MHz** 范围内快速扫描,检测 RSSI 超阈值的信号。

而需求给定的三个射频模块,其**芯片级**频率能力经核实为:

| 槽位 | 模块 | 芯片 | 芯片实际频率能力 | 来源 |
|---|---|---|---|---|
| 1 | AS10-M4463D-SMA | SI4463 | **C2A 版:142–1050MHz**<br>**B1B 版:425–525MHz** | [Si4463 规格页](https://cn.silabs.com/wireless/proprietary/ezradiopro-sub-ghz-ics/device.si4463?tab=specs)、[Si4x6x B1B vs C2A 区别](https://www.sekorm.com/news/79462573.html) |
| 2 | AS07-M1101D-SMA | CC1101 | **300–348 / 387–464 / 779–928MHz**(三个分立子带,非连续) | [TI CC1101 产品页](https://www.ti.com/product/CC1101) |
| 3 | AS01-ML01 | nRF24L01P + RFX2401C | 2400–2525MHz | 模块标称 |

### 关键歧义

模块 1 的厂商标称是 **425–525MHz**,而 SI4463 芯片本身有 **142–1050MHz**(C2A)与 **425–525MHz**(B1B)两个版本。厂商标称与 B1B 完全吻合,**强烈提示该模块搭载的是 B1B**。若如此,模块 1 对 119–1050MHz 的贡献几乎为零。

> **行动项**:向供应商书面确认 AS10-M4463D-SMA 的 SI4463 版本号(C2A / B1B)。这是决定性问题,见 §5 Q-01。

## 2. 覆盖分析(按 B1B 假设,即最坏情况)

| 频段区间 | 覆盖模块 | 状态 |
|---|---|---|
| 119 – 142MHz | 无 | ❌ **空白** |
| 142 – 300MHz | 无(SI4463 若为 C2A 可覆盖) | ❌ **空白**(除非 C2A) |
| 300 – 348MHz | CC1101 | ✅ |
| 348 – 387MHz | 无 | ❌ **空白** |
| 387 – 425MHz | CC1101 | ✅ |
| 425 – 464MHz | CC1101 + SI4463 | ✅ |
| 464 – 525MHz | SI4463 | ✅ |
| 525 – 779MHz | 无 | ❌ **空白** |
| 779 – 928MHz | CC1101 | ✅ |
| 928 – 1050MHz | 无(除非 SI4463 为 C2A 且高频匹配网络达标) | ❌ **空白** |
| 2400 – 2525MHz | nRF24L01P | ⚠️ 在 119–1050 需求之外 |

**结论:按最坏情况,119–1050MHz 中约 60% 的带宽无任何覆盖。** 这必须作为产品定义的一部分被显式承认,而不是留给实现阶段发现。

## 3. 关键区分:芯片能覆盖 ≠ 模块能覆盖 ≠ 能测到信号

即使 SI4463 是 C2A 版,也不能默认它能扫到 119MHz 或 1050MHz:

1. **匹配网络与滤波**:模块的巴伦/匹配网络与谐波低通滤波器是按目标频段设计的。425–525MHz 的模块拿到 119MHz 或 1050MHz,驻波与灵敏度都会严重劣化,发射更是不能碰。
2. **天线带宽**:SMA 天线的带宽远小于模块的调谐范围,一支 433MHz 天线在 315MHz 与 915MHz 上效率极低。
3. **"扫频"的真实含义**:本产品的扫频是**逐点调谐 + 读 RSSI**,不是宽带 FFT。所以扫描速度受"调谐时间 + 驻留 + RSSI 读取"限制,不是示波器式的瞬时全覆盖。

因此**任何"119–1050MHz 全覆盖"的宣传都需要前端硬件支撑,不能靠软件调谐实现**。

## 4. 候选方案

### 方案 A:诚实裁剪范围(最小改动)

把产品定义改为"覆盖模块实际支持的分立频段",在 App 中只展示真实可扫的区间;协议已支持这件事——`SCAN_DONE.coverage` 必须回传真实覆盖,超范围请求回 `WARN{band_clipped}`。

- ✅ 零额外硬件成本;✅ 立刻可落地;✅ 与协议契约天然一致
- ❌ 大幅偏离原始需求;❌ 缺失 868/915MHz 与低频段

### 方案 B:替换/新增宽覆盖 Sub-GHz 模块(推荐)

用一颗**连续覆盖更宽**的收发器替换或补充 M1:

| 候选 | 芯片 | 连续覆盖 | 发射 | 备注 |
|---|---|---|---|---|
| SI4432 | Silicon Labs | **240–930MHz 连续** | ≤20dBm | 一颗覆盖 CC1101 的全部断点(348–387、525–779),且能吃下 868/915MHz |
| SI4463 **C2A 版** | Silicon Labs | 142–1050MHz | ≤20dBm | 若确认拿得到 C2A 版,是**最优解**:一颗接近全覆盖 |
| CC1125 / CC1200 | TI | 164–950MHz / 410–950MHz | ≤16dBm | 高性能窄带,适合远距 |
| 宽频对数检波器(如 AD8318 / LT5534) | ADI / LTC | 1MHz–8GHz | 仅接收 | **只能测能量,不能解调**;但可作"宽带 RSSI 哨兵"快速发现目标频点,再用窄带模块精调 |

- ✅ 能真正逼近 119–1050MHz;✅ 保留原有模块作为多频段/多协议对照
- ❌ BOM 成本与体积增加;❌ 低频端(119–142MHz)仍无覆盖,需另议
- ⚠️ **注意**:仓库中 AD8318/LT5534 的型号与频段**未经本仓库核实**,选型前必须查数据手册

### 方案 C:分级产品定义(推荐与 B 组合)

把"扫频"拆成两个能力层级,分别对应两类硬件:

| 层级 | 能力 | 硬件 | 价值 |
|---|---|---|---|
| L1 宽带能量发现 | 快速找出"哪里有信号"(不认协议) | 宽频检波器 / 现有模块轮询 | 解决"范围"诉求 |
| L2 窄带解调识别 | 锁定频点,捕获时序、识别协议 | CC1101 / SI4463 / nRF24 | 解决"识别"诉求 |

这符合射频工程的真实做法,也让"119–1050MHz 快速扫描"这个需求有了一个**诚实的实现路径**:宽带发现用宽频前端,精细分析用窄带模块。

### 方案 D:不推荐——宣称全覆盖

用软件把超出能力的频段"扫一遍"并返回低 RSSI。这会产出**看起来正常但完全虚假**的扫描结果,对安防场景是危险的误导。**本仓库明确拒绝此路径**,并将其写入合规红线。

## 5. 决策

**建议:采用 C(分级定义)+ B(增补宽覆盖模块)**,并按 Q-01 的答复确定 M1 是否替换。

未决问题:

| ID | 问题 | 谁决定 |
|---|---|---|
| Q-01 | AS10-M4463D-SMA 搭载的 SI4463 是 C2A 还是 B1B? | 用户/供应商书面确认 |
| Q-02 | 是否接受新增 SI4432 或其他宽覆盖模块(成本/体积)? | 用户 |
| Q-03 | 119–142MHz 是否属于必须覆盖范围?(天线与合规双重困难) | 用户 |
| Q-04 | 868/915MHz 是否为重点频段?(需先确认国内发射合规性) | 用户 + 合规(见 60-compliance) |

## 6. 后果

### 对协议契约的影响(已落地)

- `CAPS.modules[].bands` 必须回传**模块级真实**频段,而非芯片手册频段
- `SCAN_DONE.coverage` 必须回传真实扫过的区间
- 超范围请求必须 `WARN{band_clipped}`,**禁止静默裁剪**

### 对 App 的影响

- 扫频范围选择器必须由 `CAPS` 驱动,不得硬编码 119–1050MHz
- 遇到裁剪必须在 UI 明确告知用户"实际只扫了 X–Y"

### 对产品定义的影响

- 需求 F-01 的"119–1050MHz"应改写为"覆盖所装模块的真实能力,并在 UI 中如实呈现"
- 成功判据 A-02 的比对范围随实际硬件收敛
