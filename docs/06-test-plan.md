# 测试计划与验收判据

状态:现行 · 2026-10-25 · 本批 = **USB-only**,控制载体 = **CH343P → UART0**

> **上游权威**:[01-product.md](01-product.md)(成功判据 **A-01..A-07**、约束 C-01..C-12、非目标)、
> [04-protocol.md](04-protocol.md)(字段/错误码/`CAPS` 的**唯一权威**)、[02-hardware.md](02-hardware.md)(引脚、`RF_KILL`、指示语)、
> [03-firmware.md](03-firmware.md)(固件现状与已知缺口)。机器可读镜像:`protocol/schemas/`。
>
> 本文规定"验什么、怎么验、什么算通过、拿什么当证据",不是测试脚本。
> **贯穿全文的一条原则**:拒绝必须用 **RF 侧客观证据**证明 —— "回 `tx_denied`"与"射频前端真的没发射"是两件事。
> **类型**:U=单元(PC)· I=集成(PC/模拟器)· H=HIL(真机)· F=现场(空口/人工)· ⏸=本批无前置条件 · 🔴=零容忍。

## 1. 验证层次
| 层 | 名称 | 环境 | 能验证什么 | **不能**验证什么 | 自动化 |
|---|---|---|---|---|---|
| **L0** | 单元(PC 纯逻辑) | 开发机,无射频硬件 | 帧编解码、分片/重组、RLE、特征提取、令牌校验、频段门禁与功率夹取、状态机迁移、限流器、审计格式化 | 任何真实射频行为;真实时序抖动 | ✅ CI |
| **L1** | 集成(PC,模拟器) | 以模拟 RF 后端驱动完整逻辑 | 全消息流、错误码路径、断线重连、超时、限流与抢占、能力集协商 | 真实 SPI/RMT 时序、功耗、中断延迟 | ✅ CI |
| **L2** | HIL | 真机 + 假负载/屏蔽箱 + PC | 模块驱动、SPI、RMT 采集、看门狗与复位恢复、发射时序与功率档位、审计掉电保持 | 空口传播特性、绝对辐射功率(受夹具影响) | ⚠️ 可脚本化,硬件独占须串行 |
| **L3** | 空口 | 真机 + 频谱仪/SDR + 天线 | 频率准确度、占用带宽、杂散、占空比、辐射功率、屏蔽泄漏 | 端到端用户价值 | ❌ 人工 |
| **L4** | 现场验收 | 真机 + 手机 + 被测网络 | A-01..A-07 | — | ❌ 人工 |

### 1.1 哪些必须 CI、哪些必须人工
| 归属 | 内容 | 现状(2026-10-25) |
|---|---|---|
| ✅ 必须 CI(每次提交) | 帧编解码、分片重组、RLE、特征、令牌、门禁与功率夹取、状态机、限流、审计格式化 | ⚠️ 仓库**尚无 host 测试目录**(`firmware/test/` 不存在)⇒ **L0 自动化覆盖目前为 0** |
| ✅ 必须 CI(契约一致性) | `python3 tools/validate_schemas.py` 退出码 0;`CAPS` 样例必须过 schema | ✅ 已可跑、已通过(37 个 schema) |
| 🔧 HIL(串行) | 驱动/SPI/RMT/看门狗/审计掉电保持/功率档位 | 硬件独占,不得与其他硬件任务并发(每模块独占 SPI 与天线) |
| ❌ 必须人工 | 空口 L3、屏蔽泄漏、载板点灯、`ARMED` 与 `IDLE` 的可辨识度、A-01..A-07 现场 | 无替代手段 |

## 2. 可测性要求(对固件的输入)

| # | 要求 | 违反后果 |
|---|---|---|
| T-01 | 协议编解码、分片重组、RLE、特征提取、令牌校验、频段门禁、功率夹取实现为**不依赖硬件的纯函数**(不 `#include` `esp_*.h` / FreeRTOS 头) | 混入 `ESP_LOGx`/`esp_timer` 后 PC 上编译不过,CI 覆盖归零 |
| T-02 | **单一实现,不打桩复制**:PC 测试与固件编译同一批源文件,通过构建目标切换 | 出现"测试全绿但固件是另一份代码"的假信心 |
| T-03 | RF 访问藏在可替换的 `rf_hal_t` 之后(`probe/tune/tx/idle/read_rssi/read_edges`);**模拟器必须记录每次 `tx()`**(时间/频率/功率/时长) | "拒绝"的判据是 `tx()` 调用次数 = 0,没有记录口就无法证明 |
| T-04、T-05 | **时间源可注入**(超时/`seq` 有效性/限流窗口/占空比统一走 `now_ms()`)+ **确定性**(核心路径禁 `rand()`,nonce 取自注入熵源) | 只能靠 `sleep` 计时,既慢又不确定;失败不可复现 = 没有测试 |
| T-06、T-07 | **拒绝路径可枚举**(每处拒绝都返回明确 `code`,禁止静默失败/兜底值继续)+ **审计是结构化数据**(不是 `printf`) | 越界请求"看起来成功了";逐字段断言无法实现,日志文本解析脆弱 |
| T-08 | 法定常量表独立成头文件,与运行时可写配置分离,以 `const` 编译进去 | 常量被误改时无法失败 |
| T-09、T-11、T-12 | `CAPS.modules[]` 由**真实探测**生成;`CAPS.limits.usb_frame_max`(当前 16384)为运行时数据;命中缓存与 `scan_id` 可观测(保留到下一次扫描) | `module_absent` 无法构造;换载体即静默失败;无法区分"设备丢了"与"推送被限流了" |
| T-10 | **看门狗与复位原因可观测**(正常/看门狗/异常) | TC-053 无法区分"看门狗复位"与"上电复位" |
| T-13 | 三级不确定性**真算出来**:`*_confidence` 由证据强度产出,证据不足时 `*_guess` 置 `null`;`incomplete` 由 `truncated`/丢帧传播 | 固件只填默认值时契约的不确定性表达落空,AI 仍把猜测当事实 |
| T-14 | **"静默截断"在代码层面不可达**:超承载走 `frame_too_large`、`max_edges` 超限走钳制 + `truncated`、限流丢弃走计数 + `throttled` | 三处都不得存在"截断后继续"的分支 |
| T-15 | M3 发射与控制链路的时分互斥可观测:静默窗口的申请/释放事件、窗口时长、窗口内被延迟的控制帧数 | "发射前先申请静默窗口"无法验证 |

### 4.1 A-05 的**双条件**(只有一条不算通过)

**两条必须同时成立**:①**协议层** `TX_STATUS{state:"denied", code:<明确错误码>}`;②**RF 层** `rf_hal.tx()` 计数 = 0(L0/L1)或功率计读数 = 底噪(L2)。

> 错误码只证明"代码走到了拒绝分支",不证明"射频前端没有发射",两者之间的差距正是本项目最需要验证的地方。
> ⚠️ 审计证据受限:契约尚无 `GET_AUDIT`,A-05 的"可检索"只能取自**设备侧导出**,**验收报告必须显式声明该局限**,不得把 App 镜像等同于设备审计。

### 4.2 A-06 的三个必要条件(缺一不可)

1. **协议层**:返回 `band_out_of_range` 或 `band_clipped`;`coverage` 为空或仅含真实可扫区间;
2. **不得静默成功**:响应不得是"正常完成 + `hits_total == 0`";`0 命中` 只有在请求范围确有覆盖时才合法;
3. **界面层**:App 必须把"超出本机能力"与"该频段无信号"**在视觉上区分开**。

反例(任一出现即判不通过):①`SCAN_DONE{hits_total:0, coverage:[{315e6,315e6}]}` —— `coverage` 谎报了从未扫过的区间;②回了 `WARN{band_clipped}` 但 App 只写日志、界面照常显示"未发现信号" —— 用户看不到,等于静默;③选择器允许把 315MHz 拖进选择区并点击"开始" —— 界面在**引导**用户进入不可能成功的路径(须由 `CAPS` 驱动禁用/标注)。

| 参考源优先级 | ①射频信号发生器(唯一能给出**绝对**频率基准) ②已知遥控器,**但必须用频谱仪实测其频点作参考,不得用标称值** ③RTL-SDR/HackRF 仅作相对交叉验证,须先标定 | 廉价遥控器晶振偏差可达 ±100kHz,正好是判据门限宽度;用标称值会得到虚假通过 |
| 距离/场地/极化/时序 | DUT 与参考天线 ≥3m 并做 1m/3m/10m 三点;开阔场或吸波环境;同极化等高;交替发射绝不同时;上电预热 ≥10 分钟;每点各取 3 次中位数 | <1m 处于近场;反射造成多径抖动;交叉极化恶化信噪比;同时发射互相压制;晶振温漂;单次抖动 |

**偏差归因**:近似恒定偏移或随频率线性增长 ⇒ 晶振校准问题;离散跳变或与步进相关的周期误差 ⇒ 调谐/步进量化问题。**CC1101 与 Si4463 必须分别给结论**,一个通过不能代表另一个。**A-02 只验频率不验幅度** —— RSSI 是相对量,不能反推绝对功率。


`tools/bringup_test.py` 的行为:打开端口 → 按 CH343 约定复位一次(DTR→IO0,RTS→EN)→ 等启动 → 打印启动横幅 → `HELLO` / `GET_CAPS` / `PING×3`。**全程不发 `TX_REQUEST`、不碰 `RF_KILL`**。

### 7.1 启动横幅字段判读

横幅是 **4 行以上以 `#` 开头**的文本,启动时只发一次;协议解析器只在 `MAGIC` 处开始,会把它当噪声跳过。⚠️ 复位后 ROM bootloader 自己那几行仍是 **115200**,用 921600 打开会看到一小段乱码 —— 正常。

| 行/字段 | 判读 |
|---|---|
| `# RF-Lab fw=… proto=… device=… boot` / `# carrier=CH343P->UART0 baud=921600` | 固件已起来;`device` 用于核对是否为目标板;载体与速率与 `bringup_test.py` 默认一致 |
| `# wire MISO 14: pd=… pu=…` | `pd=0 pu=1` ⇒ **floating**(MISO 未接到任何驱动);`pd=1` ⇒ 被强拉高;其余 ⇒ 被拉低 |
| `# RF_KILL=asserted(禁止发射) pairing:ok/FAILED` | 安全默认已生效;`pairing` 反映 NVS/配对初始化 |
| `# probe M1/M2/M3 … present=` | M1 需 `cts=0xFF` 且 `part=0x4463`;M2 需 `partnum=0x00` 且 `version=0x14`;M3 复位值 `config=0x08`。`present=1` **只证明 SPI 读写通**,不证明射频性能 |
| `# line M1/M2 cs_pu=…` / `# spi M1/M2 pullup=…` | `cs_pu != cs_pd` 才表示"MISO 被驱动";相等 ⇒ 选中后仍悬空。读回随上下拉变化 ⇒ 线上无人驱动,不是协议解析问题 |
| `# loop MOSI13->MISO14 hi=1 lo=0 -> PASS` | 短接 GPIO13–14 后 PASS ⇒ **ESP32 侧 SPI 外设/GPIO 矩阵正常**;FAIL ⇒ 未短接或 GPIO 损坏 |
| `# rssi 433.920MHz = …` / `# ready` | 三行 rssi 出现 ⇒ CC1101 调谐 + 接收链路真的在工作(不只是 SPI 通);`ready` = 进入帧循环 |

> ⚠️ **短接线插着时探测结果不可用**(整条 SPI 变成回环,读数变成"发出去的字节本身",如 `cts=0x00`),复测前必须拔掉。`CAPS.modules[].present=false` 是"**探过但没探到**",不是"确认没装";`CAPS.limits` 当前值:`usb_frame_max=16384`、`ble_frame_max=3600`、`max_edges=16384`、`stream_rate_hz=50`、`arm_timeout_ms=5000`。

## 8. 合规参考(本批 = 屏蔽室内使用,不作验收门)

> **前提**:产品在射频屏蔽室内使用(约束 C-09),合规认证**不作为验收门**;以下保留为实现约束与参考值 —— **屏蔽室不是理想屏蔽体,泄漏真实存在**。**新的最高优先约束不是合规而是自扰**:屏蔽室挡内外互扰,**挡不住同壳体厘米级自扰**(R-01),由 USB 有线通道(A-07)解决。

### 8.1 四道发射门(保留为实现,纵深防御)
| 门 | 判定 | 失败码 |
|---|---|---|
| **门 1** 频段白名单 | `f_hz` ∈ 某白名单条目区间;**出厂为空数组 ⇒ 拒绝一切发射** | `tx_denied` |
| **门 2** 功率上限 | `power_dbm` ≤ min(`tx_max_dbm`, `tx_power_cap_dbm`)。⚠️ 屏蔽室用途下**不再含"法定限值折算值"**这一层;`tx_max_dbm` 是模块硬件真顶(M1/M2/M3 = 20/10/20),全局 cap 出厂 **20** | `tx_denied` / 夹取并回报实际值 |
| **门 3** 显式用户确认 | 具化为**两段式发射**:第一阶段带完整参数 + 令牌 → 回 `armed`(**零辐射**);窗口内第二阶段**只带** `{armed_ack:true}` → `sent`;超时回 `failed/arm_timeout` | `tx_denied` / `arm_timeout` |
| **门 4** 有效令牌 | `HMAC-SHA256(pairing_secret, …)`,签名串含 `device_id`、`seq`、`f_hz`、`mod`、`power_dbm` + `seq` 单调 | `tx_bad_token` |

> **门 3 是唯一把"人"放进闭环的门**,必须由设备侧确认,而不是"App 说用户点了"。附加检查(各返回自己的码,不返回 `tx_denied`):P1 `not_ready`、P2 `module_absent`/`module_busy`、P3 `band_out_of_range`。
> 🔴 **P3 与门 1 必须是两道独立判定**:模块能力 ≠ 发射许可,把两者合并等于让"能调到哪里"悄悄变成"允许发到哪里"。检查顺序固定(P1→P2→P3→门1→门2→门3→门4),同一非法请求每次返回同一码。
> 🔴 **令牌有效不得放宽前三道门**(门禁设计的核心断言)。

### 8.2 红线(本批仍需成立)
| 红线 | 内容 | 落到哪个用例 |
|---|---|---|
| R1、R4 | 干扰在用的合法无线业务;在禁发频段或仅接收频段发射 | TC-035、TC-060、TC-063、TC-065 |
