# 硬件

ESP32-S3 主控 + 三个独立射频模块 + 手机 USB 有线控制。三模块**分时互斥**、共享一条 SPI2 总线,各自独立
片选/中断/模块电源(EN)/SMA 天线;M1 另有 **SDN**(GPIO9),M3 的 **CE** 由 AND(GPIO7,GPIO8) 驱动。产品见 [docs/01-product.md](01-product.md),固件见 [docs/03-firmware.md](03-firmware.md),协议见 [docs/04-protocol.md](04-protocol.md)。

## 1. 系统组成

```
                    ┌─ Type-C ①:CH343P(1a86:55d3)→ UART0 43/44 ─ 当前唯一控制通道
   手机(USB 主机)──┤
                    └─ Type-C ②:ESP32-S3 原生 USB 19/20 ──────── 本板从未枚举成功

                    ┌──────────────────────────────┐
                    │ ESP32-S3-WROOM-1   N16R8     │ 16MB Flash + 8MB PSRAM
                    │ LX7×2 @240MHz · WS2812 @48   │ 配对按键 38
                    └──┬─────────┬─────────┬───────┘
                 SPI2  │   GPIO  │   ADC   │
                       │         │         └── 电池分压 1 / NTC 2
          ┌────────────┴────┐ ┌──┴─────────────┐
          │ M1 AS10         │ │ M2 AS07        │  M3 AS01
          │ Si4463 20dBm    │ │ CC1101 10dBm   │  nRF24+RFX2401C 20dBm
          │ 425–525MHz      │ │ 387–464MHz     │  2400–2525MHz · 126 信道
          └─────────────────┘ └────────────────┘
```

M1 是 **433MHz OOK 的唯一载体**;M2 为 Sub-GHz 通用收发;M3 为 2.4GHz(带 PA/LNA/屏蔽罩)。三者共用 SCK/MOSI/MISO,仅 CS、
中断、模块电源(EN)各自独立;M1 另有 **SDN**,M3 的 **CE** 由 AND(GPIO7,GPIO8) 驱动(不新增 CE GPIO)。选「单总线 + 3 软件 CS」:同一时刻只有一个活动模块,而再开一条 SPI 主机需 3 根只能走 GPIO 矩阵的脚,余量只有 **+4**。

## 2. 开发板与平台事实

| 项 | 事实 |
|---|---|
| 开发板 / 排针 | VCC-GND **YD-ESP32-S3**(丝印 `HW678`,同设计另有 Binghe 等品牌);两侧各 22 脚,定义同 `ESP32-S3-DevKitC-1`(间距宽 1 脚) |
| 模组档位 | **HW-678A = N16R8**:16MB Flash(QIO)+ 8MB PSRAM(OPI);HW-678B 为 N8R2(8MB/2MB) |
| 供电 | 板载 5V→3.3V **LDO 1A** + 无线专用 LDO;两个 Type-C 任选其一或同时,也可从 `5V`/`3V3` 排针供电 |
| 按键 / 灯 | RST(EN)+ BOOT(GPIO0,复位后可作普通按键);**WS2812 @ GPIO48** + 红色电源灯 + TX 灯 + RX 灯 |

两个**物理独立**的 Type-C 座,插一个口只出现一个设备:

| 口 | 通路 | 实测枚举结果 | 现状 |
|---|---|---|---|
| 标注 `COM` 的 Type-C | **CH343P**(沁恒)→ UART0(GPIO43 TX / GPIO44 RX) | `1a86:55d3` → `/dev/ttyACM0`(cdc_acm),稳定可复现 | ✅ **当前唯一控制通道** |
| 另一个 Type-C | ESP32-S3 原生 USB(GPIO19 D− / GPIO20 D+),预期 VID `0x303a` | 2026-10-18:9.4 min 内 435 次 connect、438 次 `error -71`、**0 次成功**;2026-10-21 换口后 150 s 内主机侧零事件 | ❌ **从未枚举成功**,不可用,JTAG 随之失去;原因未定位(板上 `USB-OTG` 焊桥状态 **待核实**;自制载板让原生 USB 直连座子,不要照抄该焊桥) |

| 后果 | 当前状态 |
|---|---|
| 链路行为 | 控制流在 UART0,横幅与协议帧同为 **921600**,复位后 ROM bootloader 自身仍输出 **115200**;CH343P 的 DTR/RTS 接自动复位,打开端口即复位设备(固件无法规避,App 须处理"打开后重启一次") |
| App 侧 | 过滤器用 `vendorId 0x1a86 / productId 0x55d3`(CH343P 与原生 USB 都是 CDC-ACM,换的只是物理通路) |

| GPIO | 状态 |
|---|---|
| 26–32 / 33–34 | 不可用:前者被 SPI0/1 的 Flash/PSRAM 占用,后者模组根本没有引出 |
| 35–37 | **N16R8 下不可用**:模组内部已接八线 PSRAM;排针仍有丝印,接线不能照丝印 |

⚠️ **三块模块的排针形态各不相同,不能照抄**:
- **AS10**:两排 **1×6、排距 13.5mm(宽间距,非紧邻双排)**,两排焊盘**逐一对齐**;从 **SMA 端**认起(pin1 GND / pin12 VCC),该端两排焊盘均为方形。
- **AS07**:两排间距 **1.46mm**、2.54×3 **交错双排**。
- **AS01**:8 脚 **2×4 排针(2.54mm 间距)**,奇偶分列(1/3/5/7 一列,2/4/6/8 一列);以 **CE=3、CSN=4、IRQ=8** 逐脚核对。

"按同一排顺序数"必然错位;AS10 的 `SDN` **不要接 GPIO18**(那是 M1 中断脚),应接 **GPIO9(开漏)+ 100kΩ 上拉**。

### 3.2 共享 SPI2 总线

| GPIO | 信号 | 方向 | 归属 |
|---|---|---|---|
| **12** | SCK | out | 三个模块并联 |
| **13** | MOSI | out | 三个模块并联 |
| **14** | MISO | in | 三个模块并联 |
| **15 / 16 / 17** | CS1 / CS2 / CS3 | out | M1 / M2 / M3,各自低有效 |

| 参数 | 值 |
|---|---|
| 控制器 | `SPI2_HOST`;协议上报的 `bus` 是**整数 `2`**,不是字符串 `"spi2"` |
| 模式 / 时钟 | **模式 0**(CPOL=0,CPHA=0,三款芯片一致);当前 **1MHz**(三者共同的安全起点) |
| 芯片上限 | Si4463 ≈10MHz;CC1101 6.5MHz;nRF24L01+ 偏低(**待核实**) |
| 片选 | 全部**软件**控制:先拉低 → 传输 → 拉高;复位后立即拉高,避免悬空 CS 误收噪声 |

⚠️ **IO_MUX 注意**:只有 **SCK(12)是 `FSPICLK` 默认脚**;**MOSI(13)/MISO(14)不是** —— S3 的默认是 `FSPID=GPIO11`、
`FSPIQ=GPIO13`、`FSPIWP=GPIO14`,故 13/14 必须经 **GPIO 矩阵**路由(生成器与 `hardware/wiring/` 已按此更正)。
1MHz 下矩阵余量损失可忽略,提高时钟前须实测波形。CC1101 的 `CSn→SCLK` 建立时间(Table 22,不读 `CHIP_RDYn`)最小
`tSP,pd = 150µs`,固件取 200µs 并查状态字节 bit7(`CHIP_RDYn`)=0;CS 有效期间**禁止**插日志/JSON/NVS 写。

## 4. 电源、门控与本地指示

```
USB-C 5V / 18650
   └─ DC-DC 3.3V ≥2A ─┬─ 3.3V 主轨:主控 / 按键 / WS2812 / OLED(下一批)
                       ├─ LDO-A(EN←4,100k↓)/ LDO-B(EN←5,100k↓)/ LDO-C(EN←6,100k↓)
                       │    每轨 100µF+100nF×2;LDO-C 另加 470µF + π 滤波
                       └─► M1 / M2 / M3 的 VCC(标称 3.3V,实测 3.0–3.3V)

GPIO7(2.4G 总闸,上电默认低) ─┐
                             ├─ AND 门 ──► AS01 pin3 CE
GPIO8(RF_KILL,低有效,100k↓) ─┘   外部下拉 ⇒ 上电/复位/崩溃期间 CE=0
```

| 信号 | 有效电平 | 上电默认 | 作用 |
|---|---|---|---|
| LDO EN(4/5/6) | 高 | 低(模块未供电;各 100kΩ 下拉) | 每模块独立断电;M3 模块电源由 GPIO6 单独控制 |
| 2.4G 总闸(7) | 高 = 软件允许 | 低 | AND 的一路输入;与 `RF_KILL` 相与后**直接驱动 AS01 的 CE** |
| `RF_KILL`(8) | **低有效** | 外部 100kΩ 下拉 ⇒ 禁止 | 硬件发射门控;KILL 低 ⇒ CE=0 ⇒ nRF24 处于 power-down、PA 不工作 |

- **门控布尔式**:`M3 CE = GPIO7 ∧ GPIO8`(单门 AND 输出直接接 AS01 pin3 CE)。**CE=0 ⇒ 芯片 power-down、PA 不工作**;KILL 未释放时 CE 被 AND 门钳在 0。
- **KILL 保持低时 M3 仍可被探测**:GPIO6 给 LDO-C 上电、CE 保持 0,nRF24 处于 power-down,SPI 只读探测安全、不会发射;M3 若要收发必须 **GPIO7=1 且 KILL 释放**。固件启动必须**显式**把 GPIO7 驱动为 0(安全默认),与 GPIO8=0 一起保证 CE=0。
- **模块 VCC 不是精确 3.3V**:DC-DC 3.3V 经低 dropout LDO 后实测 **3.0–3.3V**;三模块均可在 **1.8–3.6V** 内工作,实测偏低不是故障(不要与 §7 的"3.3V"判据冲突)。
- 每模块独立 LDO(3.3V,**≥500mA**,带 EN)+ 就近储能:20dBm 的 µs 级电流阶跃靠 LDO 环路来不及;
  供电能力按 **>200mA** 校核(M2 手册要求 >100mA,M3 在 20dBm 时 **153mA**),峰值电流**未实测(待核实)**。

**板载 WS2812 指示语**(本批唯一的本地状态出口;同排电源灯/TX/RX 灯不受控,不计入):

| 状态 | 时序(语义靠时序,颜色只是可选增强) | 颜色 |
|---|---|---|
| `KILL`(安全态) | **常灭** | — |
| `IDLE`(就绪) | 慢闪 **0.5Hz**(1s 周期,50% 占空) | 绿 |
| `ARMED`(已武装) | 快闪 **4Hz** | 红/橙 |
| 发射进行中 | 常亮 | 红 |
| USB 链路已连接 | 叠加:每 **4s** 插一个 **50ms** 短闪 | 蓝 |
| 故障 | 急促三连闪,停 **1s**,循环 | 紫 |

- **停更即保持最后颜色**:WS2812 没有硬件"灭",`KILL` 必须由固件**显式写黑**,不能靠"不写"。
- **灯不进安全链**:"灯灭"不是"不会发射"的证据,唯一证据是 **M3 CE=0**(`AND(GPIO7,GPIO8)` 输出;KILL 低即保证 CE=0)。
- 颜色对色觉障碍、强光、山寨板(可能未焊 2812 信号)都不可靠 ⇒ 语义由时序承载,且不得用灯传凭据;驱动
  走独立低优先级任务,`rf_hal` 临界区内**不得**刷新 LED 或 OLED(下一批)。

## 5. 天线、共存与屏蔽室

| 项 | 约束 |
|---|---|
| 天线 | 三支**独立 SMA**,每个模块独占一支;**禁止并联或用合路器**(失配且破坏独占约束);天线须与模块频段匹配 |
| 间距 | 433MHz(λ≈69cm)与 2.4GHz(λ≈12.5cm):**≥17cm 为可行下限,≥35cm 为佳**;M1 与 M2 同为 Sub-GHz:**≥5–10cm** 且尽量正交 |
| 净空 / 布局 | 天线辐射体不贴电池、金属件、走线,不贴铜箔地平面;外壳用 ABS/PC 且天线区**非金属开窗**(金属壳时 SMA 穿出并良好搭接);USB 走线避开 RF 前端与 SMA 馈点,退耦电容紧贴模块 VCC(<5mm) |

| 谐波关系 | 计算 | 落点 | 判断 |
|---|---|---|---|
| 433.92 × 5 | 2169.6MHz | 低于 2400MHz | 不同频,但可能进入前端产生互调 |
| **433.92 × 6** | **2603.52MHz** | 高出 2525MHz **78.5MHz** | **不落在 2.4GHz 带内** |
| 779–928MHz × 3 | 2337–2784MHz | 与 2400–2525MHz **部分重叠** | 该段三次谐波是真实风险(模块是否自带低通滤波 **待核实**) |

**屏蔽室**挡的是内外互扰,**挡不住同壳体、厘米级间距的自扰**:M3 以 20dBm 发射时,本机 2.4GHz 接收前端
会被自己压掉(近场可达 mW/cm² 量级;阻塞门限约 −10 ~ −20dBm,具体值待核实)。本批 BLE/Wi-Fi 已移出,故无
"无线被压掉"的对象;但控制通道(USB 线 → 板载 CH343P → UART0)因此是**唯一**控制通道,它一断就完全无法指挥设备。**2.4GHz 出厂即满功率 20dBm**
(用户可调低),功率门只断言"不超过模块 `tx_max_dbm`"。

## 7. 已知接线注意与踩坑

| # | 项 | 踩错的后果 | 正确做法 |
|---|---|---|---|
| 1 | **模块 VCC 只能 1.8–3.6V** | 接 5V 直接损坏,且损坏后的现象与"没接"无法区分 | 统一 3.3V(低 dropout LDO,实测 3.0–3.3V);上电前用万用表实测 VCC–GND |
| 2 | **AS10 的 `SDN` 不能固定接 GND** | SDN 接 GND / 悬空都会让 POR 时序不可控,芯片 boot 异常:SPI 不响应、MISO 高阻,读数全 `0xFF` | SDN 接 **GPIO9(开漏)** + 外部 **100kΩ 上拉到 3.3V**;POR 脉冲:释放(上拉为高)≥100µs → 驱动低 → 等 ≥10ms 再初始化;开漏高=高阻,旧现场接 GND 不会短路但也拉不高,必须改接;不要接到 GPIO18 |
| 3 | **三块模块 VCC/CSN/CE 脚位不同** | 按"同一位置"插必错 | AS10:`VCC=12`、`NSEL=5`、`IRQ=9`、`SDN=2`;AS07:`VCC=2`、`CSN=4`、`GDO0=3`;AS01:`VCC=2`、`CSN=4`、`CE=3`、`IRQ=8` |
| 4 | **三块模块排针形态不同** | 按"同一排顺序数"错位,表现为"插上毫无响应" | AS10 两排 1×6、排距 13.5mm、逐一对齐;AS07 两排 1.46mm 交错双排;AS01 2×4 奇偶分列;都按 §3.1 脚号逐个核对 |
| 5 | **"3.3V"必须实测,但不是精确值** | 标称 3.3V ≠ 实测;欠压时模块输出高阻,读数像"没接" | 模块 VCC–GND = **3.0–3.3V**(1.8–3.6V 内正常);固件运行后 AS10 SDN 应为低;三块模块与 ESP32 **共地** |
| 6 | **原生 USB 口不可用 / USB 线必须是数据线** | 插错口或用了只有电源两芯的充电线,都表现为"App 找不到设备",用户无自排查线索 | 用开发板板载 **CH343P 的 `COM` 口**(不是 `OTG`;现场已确认)+ 数据线 + 手机侧 OTG 转接头;19/20 原生 USB 本板从未枚举成功,不要设计成控制通道 |
| 7 | **模块供电能力 >200mA** | 发射瞬态掉压 → 复位或频谱劣化 | 每模块独立 LDO ≥500mA + 就近 100µF;不共用主控的板载 1A LDO |
| 8 | **M3 的 CE 必须由 AND(GPIO7,GPIO8) 驱动** | CE 直连 GPIO 或悬空,`RF_KILL` 就形同虚设;CE 接错还会让 M3 永远 power-down | 单门 AND 输出直接接 AS01 pin3 CE;不新增 CE GPIO |
| 9 | **EN/KILL 必须有外部电阻定态** | 上电/复位/崩溃期间 EN 浮空被读成高 ⇒ 模块意外上电;KILL 浮空 ⇒ 意外允许发射 | LDO EN(4/5/6)各加 **100kΩ 下拉**、KILL(8)外部 **100kΩ 下拉**、SDN(9)外部 **100kΩ 上拉** |
