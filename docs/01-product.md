# 产品定义与范围

## 1. 一句话定位

一款由手机 App 控制、支持多频段无线收发、可接入 DeepSeek 做智能分析的便携式射频工具。

设备本体是 **ESP32-S3 + 三块直插射频模块**,操作面板是**仅 Android 的 PWA**,AI 分析在 **App 侧**完成,设备只回传特征。目标使用环境是**射频屏蔽室**,由操作者在场就地操作。

## 2. 使用场景与前提

全部使用方式都成立在同一条前提上:

> **设备与手机同处一室,操作者在场,并在操作期间与设备保持连接。**

| 维度 | 事实 | 对设计的约束 |
|---|---|---|
| 使用环境 | 射频屏蔽室 | 法规门禁降级为参考设计(C-04/C-09),但本机自扰不消失 |
| 操作者位置 | 与设备同室 | 有线连接天然满足"在场";不需要远程或挂机能力 |
| 本机自扰 | M3 以 **20dBm** 发射会压掉本机 Wi-Fi/BLE | 控制必须走不受射频影响的有线通道(F-11 / A-07) |
| 手机联网 | 屏蔽室内常无蜂窝/Wi-Fi | AI 离线兜底(F-09 本地规则库)必须真的可用 |
| 无人值守 | **不是使用方式** | 设备侧离线记录 → 回读为非目标 |

| 场景 | 内容 | 状态 |
|---|---|---|
| S1 远程部署 | 设备置于车内/背包,人远处经现场路由器遥控 | ❌ 已取消,编号永久空缺、不回填 |
| S2 近距调试 | BLE 直连,免配网,快速操作 | ⏸ 移出本批,定义保留 |
| S3 AI 分析闭环 | 特征 → DeepSeek → 类型/协议/威胁等级 → 用户确认后下发动作 | ✅ |
| S4 多模块切换 | App 内指定当前活动模块,设备加载对应驱动 | ✅ |
| S5 屏蔽室有线控制 | USB OTG 线直连,控制链路完全不走射频 | ✅ 本批唯一控制路径 |

**取消无人值守不等于取消安全网。** 看门狗、超时保护、断连归 `idle` 一条不删,职责统一表述为"**防止设备在失去控制链路后仍滞留发射态**":

- USB 断开或未连接 ⇒ 设备 **2s 内**回 `idle`、拉低 `RF_KILL`、停止发射,不得"等重连"。
- 该兜底必须**独立于链路本身**实现(最后活动时间戳 + 周期轮询),否则链路一断它同时失效。
- 中止后**不得**因链路恢复自动续发;继续发射须重走完整门禁与令牌校验。
- 本批只有一条链路 ⇒ 拔掉一根 USB 线就等于"链路全断",这条判据比多通道时更硬。

## 3. 本批范围

| 项 | 本批状态 |
|---|---|
| 控制通道 | **USB CDC-ACM 字节流,且只有这一条**。当前实现经板载 **CH343P** 桥接 **UART0(GPIO43 = TX,GPIO44 = RX)**,WebUSB 过滤器必须用精确 VID:PID **`1a86:55d3`**;ESP32-S3 原生 USB(GPIO19/20)通路在本板实测从未枚举成功,本批不作为控制通道 |
| 首次配对 | 只经 USB;`pairing_secret` 只经 USB 下发,`HELLO{pairing:true}` 不要求 `pair_code`;`pair_code` 字段保留但本批不校验。两条不可让步:**重新绑定必须由设备端物理按键确认**(USB 的在场性替代不了),**`pairing_secret` 绝不经任何人眼可读载体**(屏 / 标签 / LED 编码) |
| BLE / Wi-Fi | ⏸ 移出本批:固件不实现 GATT、WebSocket、设备 AP、`SET_NET`,但**能力定义、契约承载章节与 schema 字段(`ble_frame_max` / `ble_frag_total_max`)全部保留**;`no_display` / `ble_only` / `bad_code` 三个错误码本批无活路径,不要为其造路径或用例 |
| App 载体 | **仅 Android 的 PWA**;传输层 = 一层抽象 + 两个同形后端,基线 **WebUSB + `web-serial-polyfill`**,`navigator.serial` 仅作探测成功时的优先项;不得把 Web Serial 写成硬依赖(Android 的 Web Serial 迟至 Chrome 148) |
| App 连接体验 | 首次连接会弹**两次**系统授权框(`requestDevice` 后与 `open()` 时);CH343P 的 DTR/RTS 接了自动复位,打开端口会让设备重启一次,App 必须能处理;不得向用户承诺"自动重连、无需交互" |
| OLED 显示 | ⏸ 延后到下一批:引脚(GPIO40/41)与 I²C 4 针 SSD1306/SH1106 选型保留,本批不装、不写驱动 |
| 本地指示 | **没有蜂鸣器**(GPIO39 已释放回可用池);唯一载体是板载 **WS2812(GPIO48)**。语义由**闪烁时序**承载、颜色只作增强;它停更即保持最后颜色,故 `KILL` 必须显式写黑,且"灯灭"不得当作"不会发射"的证据(唯一证据是 `RF_KILL` 硬件门控) |
| AI 分析 | 在 **App 侧**调用 DeepSeek;设备不持有 API Key、不发起任何 AI 网络请求 |
| 射频模块 | 三块即最终配置,不增补(见 §4) |

## 4. 硬件配置与频率覆盖

主控:**ESP32-S3N16R8** — Xtensa LX7 双核 240MHz、16MB Flash、8MB PSRAM、片内 2.4GHz Wi-Fi + BLE。开发板:**VCC-GND YD-ESP32-S3**(丝印 `HW678`),两个物理 Type-C 口,无 HUB。安全门控 **`RF_KILL` = GPIO8,低有效**。

| 编号 | 型号 | 芯片 | 模块级频段 | 功率 | 接口 / 尺寸 | 调制能力 |
|---|---|---|---|---|---|---|
| M1 | **AS10-M4463D-SMA** | Silicon Labs SI4463 | **425–525MHz** | **20dBm / 100mW** | 4-Pin 硬件 SPI,24×16mm 直插 | **OOK/ASK + FSK 族**;灵敏度 −126dBm@1kbps |
| M2 | **AS07-M1101D-SMA** | TI CC1101 | **387–464MHz**(推荐 433±10MHz) | **10dBm / 10mW** | DIP 直插,28×15mm | 模块手册只列 2-FSK / GFSK / MSK,**无 OOK**;灵敏度 −111dBm@1.2kbps |
| M3 | **AS01-ML01**(无后缀) | Nordic nRF24L01P + **RFX2401C** PA/LNA | **2400–2525MHz**(126 信道) | **约 20dBm / 100mW** | SPI,18×33.3mm 直插,SMA-K,带屏蔽罩 | GFSK |

三条会改变实现的硬事实:

1. **频率能力按模块算,不按芯片算。** SI4463 芯片可 142–1050MHz、CC1101 芯片有三段(300–348 / 387–464 / 779–928MHz),但 AS10 模块被前端裁到 425–525MHz、AS07 被裁到 387–464MHz。要更宽必须换模块,换芯片版本无效。
2. **433MHz OOK 遥控器/传感器只能由 M1 承担。** AS07 模块官方调制栏不含 ASK/OOK(官方原文另称其 2-FSK"与使用 ASK 的简单遥控器不兼容"),M3 在 2.4GHz、与 433MHz OOK 无关。A-03 及所有 OOK 相关验收绑定 M1。
3. **覆盖 = 387–525MHz(138MHz,约占 119–1050MHz 的 15%)+ 2400–2525MHz。** 空白 **119–300 / 525–779 / 928–1050MHz 物理上不可及**;315MHz 与 868/915MHz 恰好都落在空白内。

空白必须**可见地失败**(A-06):完全带外 → `ERROR{band_out_of_range}`,不下发调谐命令;部分带外 → `WARN{band_clipped}` + `SCAN_DONE.coverage` 给出真实扫过的区间;App 必须显著提示"该频段不在本机能力内"。**禁止**返回空结果让界面显示"无信号"。

功率规则:**所有模块按各自 `tx_max_dbm` 满功率出厂**(M1/M3 为 20dBm,M2 受硬件限制只有 10dBm,不是被策略限住),全局 `policy.tx_power_cap_dbm` = **20dBm**,逐次发射的有效上限 = `min(请求值, 全局 cap, 该模块 tx_max_dbm)`。功率必须能由用户在 App 内按模块调节(步进 ≤1dB),界面显示设备回报的实际生效值 `granted_power_dbm`;降低功率不需额外确认,提高需要确认。

## 5. 功能需求

| ID | 需求 | 优先级 | 备注 |
|---|---|---|---|
| F-01 | 自动扫频:在活动模块的真实频段内快速扫描,报告 RSSI 超阈值的信号 | P0 | 带外必须可见地失败(见 A-06) |
| F-02 | RSSI 实时读取,用于信号检测与阈值触发 | P0 | OOK 相关路径绑定 M1 |
| F-03 | 原始数据捕获:保留 OOK/FSK 原始时序特征 | P0 | 依赖 RMT + SPI 高速读取;OOK 仅 M1 |
| F-04 | 信号解码:通用特征层 + 协议指纹库,识别遥控器、传感器 | P0 | 433MHz OOK 遥控器只能经 M1 捕获 |
| F-05 | 信号发射:复现/模拟目标信号 | P0 | 四道门禁 + 人工二次确认;审计保留 |
| F-06 | 多模块兼容:按用户配置加载 CC1101 / SI4463 / nRF24L01 驱动 | P0 | 每模块独立 SPI、独立天线 |
| F-07 | App 同室无线控制(Wi-Fi 经路由器或设备 AP) | ⏸ 本批不做(原 P0) | 能力定义保留,非取消 |
| F-08 | App 近距控制(BLE 直连) | ⏸ 本批不做(原 P1) | 能力定义保留,非取消 |
| F-09 | DeepSeek 智能分析(类型/协议/威胁等级) | P1 | App 侧调用;屏蔽室内可能无网,离线兜底必须可用 |
| F-10 | 依 AI 结论回下发动作指令(发射/保存) | P1 | AI 只给建议,发射仍需人工二次确认 |
| F-11 | App 有线控制(USB,经 OTG 线) | P0 | 本批唯一控制通道;手机作 USB 主机、设备作 CDC-ACM 从设备;与无线共用同一套协议语义,不新增消息类型 |

**明确不做(非目标)**:

- ❌ 通用频谱分析仪(无扫频前端、无校准功率测量)。
- ❌ 解调任意未知协议;只做已知协议指纹 + 通用特征描述。
- ❌ GSM / LTE / Wi-Fi / 蓝牙的**数据包解码**;2.4GHz 只做能量与 nRF 私有包。
- ❌ 绕过任何加密或访问控制。
- ❌ 发射功率的精确标定(只做档位控制)。
- ❌ 设备侧离线记录 → 回读;设备独立挂机;设备间互联或中继。
- ❌ 云端服务端、设备注册、账号体系、远程穿透。

## 8. 关键决策摘要

**ADR-0001 频率覆盖:接受空白,不增补硬件**
- 决策:F-01 的 119–1050MHz 收敛为所装模块真实频段(387–525MHz + 2.4GHz),只做诚实裁剪。
- 理由:模块前端把芯片能力裁掉,硬件已采购完毕;增补模块的成本与体积收益不成比例。
- 影响:CAPS、扫频 UI、F-01、A-02 全部按模块能力书写;带外必须可见地失败(§4 / A-06)。
- 放弃:宽覆盖模块(SI4432、未裁剪 CC1101、CC1125)、宽频检波器哨兵、宣称全覆盖。

**ADR-0002 AI 分析放在 App 侧**
- 决策:App 调用 DeepSeek,设备只提取并回传 `features`,不持 Key。
- 理由:密钥最小暴露、TLS 内存留给射频、换模型/提示词无需刷固件、离线兜底在手机侧可行。
- 影响:`features` 必须自包含(设备无法追问);App 做特征哈希去重与上传字段告知;AI 结论绝不自动触发发射。
- 放弃:设备直连 API(密钥物理暴露 + 现场网络不可控)、两者可切换(两套密钥管理)。

**ADR-0003 USB 有线控制通道**
- 决策:用 USB CDC-ACM 作为第三条传输,承载既有帧格式,不新增消息类型。
- 理由:射频干扰对有线无效,能在 2.4GHz 发射期间保持中止能力;公用协议语义。
- 影响:F-11 / C-10 / A-07;USB 是唯一可信配对信道(物理在场由连接行为证明);协议帧与载体解耦,物理通路现为 CH343P(§3),帧层无需改动。
- 放弃:USB-OTG 外设 + TinyUSB(需外接 PHY 或烧 eFuse,失去 JTAG)、设备作主机、只靠时分。

**ADR-0004 取消无人值守远程部署**
- 决策:取消 S1;使用前提收缩为"同室、在场、保持连接"。
- 理由:该场景是离线记录、远程通道、后台保活等一批要求的唯一来源,用户已不需要。
- 影响:设备侧离线记录/回读转为非目标;**看门狗、超时、断连归 idle 全部保留并升级为首要防线**。
- 放弃:保留无人值守并把记录责任交给设备(需新消息对 + 无 RTC 的时间基准);只删文案不动下游(会留下无人验证的安全网)。

**ADR-0005 本批只做 USB,BLE/Wi-Fi 延后**
- 决策:本批不实现 BLE GATT 与 Wi-Fi/WebSocket/AP/配网;能力定义与 schema 字段原样保留。
- 理由:远程定位已消失,BLE 无配对职责,`wss` 信任模型在 PWA 上无解;而删定义会让下一批重推并重蹈旧错。
- 影响:控制通道塌缩为单点——USB 一断即无法指挥,包括无法中止发射;WebUSB 实测升为发布门禁;断连兜底不得依赖链路。
- 放弃:删除无线能力定义;顺带删掉 Wi-Fi 全套(取舍未做,已先延后)。

**ADR-0006 控制载体:WebUSB 基线 + `web-serial-polyfill`**
- 决策:一层传输抽象 + 两个同形后端,基线 WebUSB,`navigator.serial` 仅作优先探测。
- 理由:Android 的 Web Serial 迟至 Chrome 148,作基线会把最低系统要求钉在 148+ 且失败表现与设备故障不可区分;polyfill 就是 Web Serial 规范的原型实现。
- 影响:设备过滤器必须用精确 VID/PID(`1a86:55d3`,见 §3),不得按通用 CDC 类过滤;不得在 Windows 上自测 WebUSB;`claimInterface` 错误必须原样上报。
- 放弃:只用 Web Serial(把最低系统要求钉到 Chrome 148+)、自研 CDC 封装、直接上原生 Android 壳(保留为降级路径)。

## 9. 术语表

| 术语 | 定义 | 不要这样用 |
|---|---|---|
| RSSI | 接收信号强度,单位 dBm,扫频判据 | — |
| 噪底 | 无信号时的本底噪声电平,用于判断信号是否显著 | 不要把 RSSI 单独当"有信号" |
| 扫频 | 逐点调谐 + 读 RSSI,不是宽带 FFT | ❌ 说成"瞬时全覆盖" |
| 驻留时间 / 步进 | 每个频点停留时长 / 相邻频点间隔 | — |
| OOK / ASK | 用有无载波表示 0/1,433MHz 遥控器最常见 | — |
| (2-)FSK | 用两个频点表示 0/1,传感器与数传常见 | — |
| 跳变序列 / RLE | 电平变化的时间点序列,按"间隔 + 电平"成对存储 | — |
| 特征 `features` | 设备从原始跳变序列归纳出的结构化描述 | ❌ 不要把原始码流叫"特征" |
| 原始码流 | RLE 编码的跳变序列本身 | ❌ 不要叫"原始数据" |
| 活动模块 / 槽位 | 同一时刻唯一可收发的模块,`slot ∈ {1,2,3}`,由 `SELECT_MODULE` 指定 | ❌ "同时用三个模块扫频" |
| 频段裁剪 | 请求范围超出模块能力被夹取到真实区间,须回 `WARN{band_clipped}` | ❌ 静默裁剪 |
| 发射门禁 | 设备侧四道校验:①频段白名单 ②功率上限 ③显式用户确认 ④令牌 | ❌ 叫"发射配置";❌ 把功率门当法规限幅 |
| 令牌 `auth_token` | App 计算的 HMAC 授权凭证,靠单调 `seq` 防重放(设备无 RTC,不用时间窗) | ❌ 叫"密码/API Key";❌ "30s 有效" |
| `granted_power_dbm` | 实际生效功率 = `min(请求, 全局 cap, 模块 tx_max_dbm)`,UI 与审计都用它 | ❌ 与请求值 `power_dbm` 混用 |
| 能力集 `CAPS` | 设备上报的真实硬件能力,App 的唯一真实来源 | ❌ App 硬编码频段/功率 |
| 审计日志 / 信号库 | 每次发射请求(含被拒)的本地记录 / 用户主动保存的信号 | ❌ 两者混为一谈 |
| 威胁等级 | `info` / `low` / `medium` / `high` / `unknown` 五档 | ❌ 新增档位 |
| 配对码 `pair_code` | 6 位一次性码,本批无载体、不校验,字段保留 | ❌ 与长期密钥 `pairing_secret` 混用 |
