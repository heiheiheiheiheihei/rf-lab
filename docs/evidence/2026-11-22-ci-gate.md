## 2. 三个根因与修法

1. **平台没锁版本。** 本机是 dev `espressif32@55.03.311`(ESP-IDF 5.5.5),
   CI 解析到稳定 `8.0.0`,GCC 把 `-Wformat-truncation` 升级成错误,共 5 处:
   `net.c` 的 AP/STA SSID、STA password、`main.c` 的 OTA 横幅、`web_server.c` 的明文命令。
   修法:给 `snprintf` 显式 precision(`sizeof(dst) - 1`),语义与原来一致;
   OTA 横幅按 token 缓冲留足;删掉 `load_ble_pin` 的未用变量。
2. **`EMBED_FILES` 在 PlatformIO 的相对 `BUILD_DIR` 下坏掉。**
   ESP-IDF 把生成的 `.S` 放到 `<BUILD_DIR>/index.html.gz.S`,PlatformIO 给的是相对路径
   (`.pio/build/esp32c3`),CMake 再拼一次 → 去 `.pio/build/esp32c3/.pio/build/esp32c3/...` 找源文件。
   **本机构建一直没暴露**:`.pio/build` 里留着更早一次成功构建的 `.S`;清空 build 目录才会重现。
   修法:`scripts/embed_web.py` 生成 `firmware/src/web/web_ui_gz.S`
   (`.incbin "绝对路径"`),作为普通 `SRCS` 编译;不再用 `EMBED_FILES`。
   生成物进 `.gitignore`,不污染 `build=` 的 dirty 判断。
3. **平台版本选择。** `55.03.311` 是**不在 registry** 的 dev 版本(CI 装不到);
   `8.0.0` 的 `EMBED_FILES` 行为如上。最终 `platformio.ini` 锁 **`espressif32@7.1.3`**
   (registry 上最近的稳定版,ESP-IDF 与 5.5.x 同代)。

**Avoided misfix**:没有关掉 `-Werror`、没有全局加 `-Wno-format-truncation`、没有把
`PROJECT_BUILD_DIR` 硬编码成绝对路径(不可移植),也没有对 master 强推。
