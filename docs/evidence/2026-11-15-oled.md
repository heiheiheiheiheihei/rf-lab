OLED 计数器而暴露出来的**长发/停止应答修正**。结论汇总在
[`../00-mvp.md`](../00-mvp.md) §5.3、§10.2、§11。

## 3 状态页(帧缓冲解码)

`DISP SHOW` 输出的是**我们写进 SSD1306 的帧缓冲**,不是从玻璃回读(SSD1306
I2C 不支持读回 GDDRAM)。为便于复核,用同一份 5×7 字库把 40 行 ASCII 反解成
文本;以下每一条都与 `DISP SHOW` 的 40 行输出一一对应。

### 3.1 学码

按原遥控器后,屏上内容解码为:

```
LEARN ID 5
433M
5555033C
saved 5/32
F6 A1 S0
```

同时串口 `INFO`:`stored=5/32 rx_bytes=49 frames=6 acks=1 stray=0`。
**注意**:这一条记录是 `433M`,而遥控器是 315M,见 §5 的异常记录;
`LEARN/RX` 页本身显示的是模块实际给出的频段,不是固件猜的。

### 3.2 已知码回读

同一把 315M 遥控器再按一次:

```
RX ID 2
315M
5555033C
known
F1 A118 S0
```

→ 这次模块报 `315M`,命中已有的 id=2;屏上 `known` 与串口 `RX id=2` 一致。

### 3.3 单次发射

```
TX ID 1 OK
315M
5555034C
F0 821ms
F0 A1 S0
```

`SEND 1` 串口同时给出 `ACK 0xF0 TX_OK` / `OK tx ...`;屏上显示实测耗时。

### 3.4 长发/停止

```
LONG ID 1            STOP ID 1
315M                 315M
5555034C             5555034C
until STOP           stopping
F0 A79 S0            F0 A118 S0
```

`LONG` 期间 `A` 随 `0xFE` 心跳增长(79→118);`S` 保持 0。这直接说明
"长发期间的字节不是 stray",见 §4。

### 3.5 空闲页

上电 1.5s 后回到空闲页(最后一条码来自 NVS):

```
RF-Lab 0.5.0
READY 5/32
5555033C
433M id=5
F0 A0 S0
```

`id=5 / 433M` 就是 §5 的异常记录;屏没有替固件"美化"频段,这点是刻意的。

## 4 关键修正:长发/停止不是"无应答"

0.4.0 的结论是"`LONG`/`STOP` 后模块不回任何字节,用 `MON` 逐字节确认过"。
0.5.0 的 OLED `S` 计数把它推翻了:`LONG` 后 `stray` 持续增长。

带主机时间戳的 `MON` 原始抓包(`LONG 1` 后约 4s 发 `STOP 1`):

```
0.424  MON TX FD F3 FE 55 55 03 4C DF
0.586  MON RX FE        ← 命令后 ~162ms 出现第一拍
0.646  MON RX FE
0.687  MON RX FE
...                     ← 约每 40ms 一拍,≈25Hz,持续整个长发期间
4.440  MON TX FD F3 FF 55 55 03 4C DF
4.481  MON RX FE        ← 停止命令后在途的一拍
4.481  MON RX FF        ← 停止状态
(之后无字节)
```

结论:

| 命令 | 模块返回 | 时间 |
|---|---|---|
| `LONG`(dur=0xFE) | `0xFE` 周期心跳 | 首拍 ~0.16s,之后 ~25Hz |
| `STOP`(dur=0xFF) | 可能先收到一个 `0xFE`,再 `0xFF` | ~0.02–0.05s |
| 单次发射(dur=0x03) | `0xF0` | ~0.85s(未变) |

固件 0.5.0 已把 `0xFE`/`0xFF` 纳入 `rf34dl_is_ack()`:

```
>>> LONG 1
ACK 0xFE LONG_ON
OK long id=1 band=315M code=5555034C (0xFE, 170ms)
>>> STOP 1
ACK 0xFE LONG_ON
ACK 0xFF STOPPED
OK stop id=1 band=315M code=5555034C (0xFF, 23ms)
```

修正后连续 `LONG`/`STOP`:`stray` 保持 0,`acks` 随心跳增长。

**仍未证明**:`0xFE` 心跳只能证明模块处于长发状态,不能证明射频真的持续输出;
需要看原接收器是否持续动作,见规格 AC-7。

## 5 未解释的 433M 记录

本次学码把两条新码写进了 NVS:

```
 4  433M 5555034B
 5  433M 5555033C
```

它们与已有 315M 码的 4 字节值相同(id=2/3),但频段字节是 `F4`。之后同一把
315M 遥控器再按一次,又正常回 `RX id=2 / 315M / 5555033C`(见 §3.2)。

可能原因(未定论,不据此改代码):

1. 当时按的是另一把 433M 遥控器,码值恰好相同(EV1527 码空间可碰撞);
2. 模块偶发把同一 315M 信号判成 433M(`F3→F4` 不是单比特错,需两次位错);
3. 其他 433M 突发被解码。

处置:保留两条记录,不删、不改;在规格 §10.2 标为**未解释**。后续可用
`MON ON` + 同一遥控器连续按 20 次,统计 `F3/F4` 帧比例来定性。

## 6 开关与图案的生命周期

```
>>> DISP TEST 3
OK disp=test 3s (DISP ON to leave test)
(3s 后 DISP SHOW 回到 STOP ID 1 状态页)
>>> DISP OFF
OK disp=off
>>> DISP
OK disp=off present=yes test=off flush=54 err=0
>>> DISP ON
OK disp=on
```

- `DISP OFF` 发 `0xAE`,显存保留;`DISP ON` 发 `0xAF` 并立即重绘。
- `DISP TEST <s>` 到期自动回状态页;`DISP ON` 可提前退出。
- `DISP SHOW` 在屏关/屏不在时仍工作(只读 RAM 帧缓冲)。
