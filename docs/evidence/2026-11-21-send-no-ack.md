## 4 判读

| 排除项 | 依据 |
|---|---|
| 433M 码非法 / 模块不支持 433 | 315M 的已验证码同样 0 应答 |
| 1500ms 窗口太短(旧的 500ms 误报同类) | 3s 观察窗 + 10s 空闲都没有迟到字节,`acks=0` |
| 模块卡在长发 | 长发会以 ~25Hz 发 `FE`,`rx_bytes` 会涨;实测不动 |
| 波特率错位 | `RECOVER` 扫了 4 个波特率;且当前 5 帧按 9600 解析全对 |
| TXD/RXD 接反、共地、电平 | 解码帧完整无 stray;接反/共地不良会先乱在 RX 上 |

**剩下唯一自洽的解释:ESP GPIO3 → 模块 RXD 这条单向链路没有送达**
(杜邦线/焊点开路、GPIO3 或模块 RXD 输入损坏)。模块的接收与解码是两条独立路径,
所以「按遥控器有 LEARN、发命令没反应」可以同时成立。

时间线补充:`firmware/src/main.c` 的发射/等应答路径最后修改于 11-15 12:46,
当前固件 11-21 13:11 构建;11-15 13:01 的 `ACK 0xF0` 证据用的就是同一套命令路径
→ **不是 0.6.0 的软件回归**。

## 7 追加:21:25 按键原始字节 —— 模块活着,但每帧只吐 1 个 0x00
