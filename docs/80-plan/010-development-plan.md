## 1. 本批范围(一句话)

**做出一台能用手机 App 经 USB 线就地操作的 ESP32-S3 多频段射频实验平台,在屏蔽室内完成扫频 / 捕获 / 特征提取 / 受控发射,(可)接入 DeepSeek 分析。**

| 维度 | 本批**做** | 本批**不做**(理由见括号) |
|---|---|---|
| 控制通道 | **仅 USB 有线**(ADR-0003/0005) | BLE、Wi-Fi/WebSocket(移出本批,**能力定义与 schema 保留**) |
| App 载体 | **PWA(Android)**(ADR-0006 核实通过) | iOS(已放弃)、原生 Android 壳(仅作降级路径) |
| 显示 | **无屏**;本地指示 = 板载 WS2812 一颗 | OLED(延期下一批,**引脚与选型保留**) |
| 场景 | 操作者在场、连接保持(ADR-0004) | 无人值守 / 远程部署(`S1` 已取消) |
| 合规 | 屏蔽室内使用,合规文档降级为**参考设计** | 合规认证不作为验收门 |
| 固件 | ESP-IDF,三射频模块统一驱动接口 | OTA(契约占位)、设备侧离线记录(非目标) |

## 2. 阶段与门禁(总览)

```
阶段 0  可行性门禁 ──── 🔴 阻塞级:不过则后续全部重做
   │      V-17/TC-074a:WebUSB 能否 claimInterface + 确切 PID
   │      V-15:WS2812 停更保持颜色?RMT 冲突?
   │      V-16/TC-106:载板是否正品(灯会不会亮)
   ▼
阶段 1  固件骨架 ──── 能烧进去、能通帧、能点灯、能门控
   │      出口:USB 上跑通 HELLO/GET_CAPS,RF_KILL 可切
   ▼
阶段 2  射频驱动 ──── 三模块 probe/调谐/RSSI
   │      出口:A-02 频率准确性 ±100kHz
   ▼
阶段 3  捕获与特征 ── RMT 捕获 → RLE → features
   │      出口:捕获-复现闭环 A-03
   ▼
阶段 4  发射门禁 ──── 8 步门禁 + 审计 + 令牌
   │      出口:四道门禁**真实拒绝**可复现
   ▼
阶段 5  App ───────── PWA:载体层 + 业务 UI
   │      出口:A-01 30s 内连接
   ▼
阶段 6  联调与验收 ── A-01..A-07、长稳、HIL
```

**每个阶段必须"退出即验证"** —— 不得把验证堆到最后。阶段 0 是**唯一**允许阻塞前置的阶段。

## 3. 阶段 0:可行性门禁(🔴 阻塞级)

> **为什么单列成阶段**:这三项都是"**结论无法从手册推出,只能实测**"的事实,而它们**各自能推翻一个已定的设计**。放在最后会发现返工成本极高。

### T0.1 🔴 WebUSB 访问实测(V-17 / TC-074a)—— **最高优先**

| 项 | 内容 |
|---|---|
| **目标** | 确认 Android Chrome 经 OTG 能访问原生 USB 的设备,并取得**确切 PID** |
| **前置** | 开发板(跑一个 USB Serial/JTAG echo 固件)、Android 手机、OTG 线、**一个最小 HTML 测试页** |
| **⚠️ 第 0 步(先做,别跳)** | **裸板插原生 Type-C 口,先用主机 `lsusb` / 设备管理器确认能否枚举到 VID `0x303a`。**<br>🔴 **若枚举不到,先怀疑板上的 `USB-OTG` 焊桥(见 040 **V-19**),不要先怀疑固件或线材** —— 该焊桥若出厂断开,现象与"固件没起来/线坏/驱动问题"**完全无法区分**,会在这一步浪费大量排查时间 |
| **步骤** | ①(见上)裸板枚举确认;② 插**原生 USB 口**,`navigator.usb.getDevices()` + `requestDevice()` 打印**全部**设备的 `vendorId/productId/productName`;<br>③ `claimInterface()`;<br>④ `transferOut`/`transferIn` 字节回环;<br>⑤ 插 **CH343P 口**重复 ②,记录其 VID(`0x1a86`);<br>⑥ 用 `{classCode:2}` 宽泛过滤器试一次,看是否把 CH343P 一并匹配(用于确认"必须精确过滤"是否仍必要);<br>⑦ 经 `web-serial-polyfill` 再跑一次回环(ADR-0006 基线后端) |
| **通过判据** | ① 原生 USB 枚举出(VID `0x303a`);② `claimInterface` **成功**;③ 回环正确;④ **记录确切 PID**;⑤ polyfill 路径同样能回环 |
| **失败后果** | 🔴 触发 **ADR-0003 §6 降级路径**:改用**原生 Android USB Host 小壳**(只包 USB 读写,业务逻辑仍在 Web 层)。⚠️ **本批不存在"退回无线"这一选项**(ADR-0005) |
| **产出** | 实测记录写入 F-6 的 **V-17**(关闭)+ 固件/App 的 `filters` 常量 |

**⚠️ 三项纪律**:

1. **在 T0.1 通过前,不要把 PID 硬编码进任何代码**。
2. **桌面自测走 Linux/macOS**;⚠️ **不要在 Windows 上自测 WebUSB**(V-18:必然失败且会被误判为固件缺陷)。
3. **同时验证 polyfill 路径**(ADR-0006 后端 B)—— 因为它是**基线**;若 polyfill 在本设备上不工作,须立即记录并评估后端 A 的地位。

### T0.2 🟠 WS2812 行为实测(V-15)

| 项 | 内容 |
|---|---|
| **目标** | 确认①"数据线停更 → 保持最后颜色"在**本板**成立;②驱动(RMT)与射频事务不冲突 |
| **步骤** | 写入某颜色 → 挂起驱动任务 / 触发看门狗复位 → 观察 LED 是否保持颜色;再在 M3 发射期间刷新 LED |
| **通过判据** | 行为符合预期,**且**要在固件里据此写死:`KILL` **必须显式写黑**(不能靠"不写就会灭") |
| **失败后果** | 若停更即灭:反而更安全,但仍**不得**把"灯灭"当作"不会发射"的证据(唯一判据是 `RF_KILL` 硬件门控)。若 RMT 冲突:LED 降级为"低频刷新"或改 GPIO 方案 |
| **关联** | 硬件文档 §2.7、TC-105/105b/105c |

### T0.3 🟠 载板真伪抽查(V-16 / TC-106)

| 项 | 内容 |
|---|---|
| **目标** | 确认手上这块**不是**山寨板,且 WS2812 **真的会亮** |
| **步骤** | 实机点灯 + 核对丝印/版本号(正版为 1.4 版) |
| **通过判据** | LED 能亮 |
| **失败后果** | 🔴 **本地状态出口静默失效**,且操作者会把"灯不亮"误读为"设备未在发射" ⇒ 换板,或**必须**另行引入状态出口 |
| **关联** | R-18 |

> ⚠️ **阶段 0 的出口条件**:T0.1 **必须通过**(或已明确走降级路径);T0.2/T0.3 必须**有结论**(通过或已决定处置)。
> **在此之前不要开始阶段 1 的批量编码** —— 但**可以先写 host 侧纯逻辑**(见 §4.0,不受硬件阻塞)。

## 4. 阶段 1–6:任务分解

> **TDD Route**:`off` → 决策 **`skipped`**。本批按仓库既有测试策略执行(host 单元测试 + HIL + 协议一致性),**不引入 strict RED/GREEN 纪律**(用户未要求 TDD,项目 `tdd_mode = "off"`)。
> **交付物形态**:阶段 1–6 的**具体实现任务清单不在本文件展开** —— 它们由各领域文档的"待决问题/测试义务"驱动,本文件只定**阶段门禁与顺序**。理由:把实现任务写进本文件会立刻与固件/App 文档产生**双份真相**。

### 4.0 可并行项(不被阶段 0 阻塞)

| 任务 | 说明 |
|---|---|
| `proto` 帧编解码 + 分片重组 | **纯逻辑**,依赖 cJSON + C 标准库,**可 host 编译**(固件文档 §1.2) |
| `features` 特征提取 | 同上;用录制语料做回归 |
| `policy` 白名单 / 功率取 min / HMAC 校验 | 纯逻辑,host 可测 |
| `protocol/schemas/` 一致性校验 | 已存在 `tools/validate_schemas.py`,可直接扩展 |
| App 的**载体层**(ADR-0006 双后端) | 可用 mock 字节流开发,**不必等固件** |

> 🔑 **这是本计划最重要的一条排期结论**:**阶段 0 只阻塞"碰硬件的代码"**。占本批工作量最大的纯逻辑部分(proto/features/policy/App 载体层)可以**立即开工**。

### 4.1 各阶段出口判据

| 阶段 | 出口判据(全部可测) | 关联 |
|---|---|---|
| 1 固件骨架 | 能烧录;USB 上跑通 `HELLO` → `HELLO_ACK` → `GET_CAPS` → `CAPS`;`RF_KILL` 可切且状态可查;WS2812 按指示语点亮 | TC-074/074i、F-Q12 |
| 2 射频驱动 | 三模块 `probe` 认出;调谐落在 ±100kHz;RSSI 读回合理 | **A-02** |

| 4 发射门禁 | 四道门禁**各自**能真实拒绝;审计**先写后发**;令牌校验含 `seq` 单调性 | TC-035..047、TC-104 系列 |
| 5 App | A-01 30s 内连接(含首次授权与免弹窗两种情形);拔线**立刻**感知并给出**具体原因** | A-01、TC-074e |
| 6 验收 | A-01..A-07 全部;24h 长稳(全程在场 + USB 全程连接,**含中途拔线**) | §5 |

## 9. 本计划的自我约束

1. **不制造双份真相** —— 本文件不复述引脚表/消息定义/判据数值,只引用。
2. **结论必须可追溯** —— 每个"已定"都指向 ADR 或 F-x。
