# 产品定义与范围

状态:`draft` · 最后更新:2026-09-20 · 上游依据:用户需求(本仓库初始化时提供)

## 1. 一句话定位

一款由手机 App 灵活控制的、支持多频段无线收发的、可接入 DeepSeek 进行智能分析的便携式射频工具。

## 2. 目标用户与场景

### 2.1 目标用户

| 角色 | 诉求 |
|---|---|
| 射频/嵌入式学习者 | 低门槛观察真实空口信号,理解 OOK/FSK 与协议结构 |
| 自有设备所有者 | 排查自家遥控器、门磁、传感器、无线开关的频点与协议 |
| 安防/合规自查人员 | 在授权范围内发现异常发射源并留存证据 |

### 2.2 核心使用场景(来自需求)

- **S1 远程部署**:设备放在车内/背包中,接入现场路由器 Wi-Fi;人在远处用手机 App 远程控制扫频、解码、发射。
- **S2 近距调试**:手机与设备 BLE 直连,免配网,快速操作与实验。
- **S3 AI 分析闭环**:App 把捕获的信号特征上传 DeepSeek → 得到信号类型/协议/威胁等级 → App 依结论下发指令(发射响应、保存信号)。
- **S4 多模块切换**:用户在 App 内配置当前使用哪个射频模块(CC1101 / SI4463 / nRF24L01…),设备加载对应驱动。

## 3. 功能需求

| ID | 需求 | 优先级 | 备注 |
|---|---|---|---|
| F-01 | 自动扫频:目标频段内快速扫描,检测 RSSI 超阈值的信号 | P0 | 频段范围受模块能力约束,见 ADR-0001 |
| F-02 | RSSI 实时读取,用于信号检测与阈值触发 | P0 | |
| F-03 | 原始数据捕获:保留信号时序特征(OOK/FSK 原始码流) | P0 | 依赖 RMT / SPI 高速读取;**OOK 路径仅 M1(SI4463)可用**,见 §6.2 |
| F-04 | 信号解码:识别遥控器、传感器等协议 | P0 | 分两层:通用特征层 + 协议指纹库;**433MHz OOK 遥控器只能经 M1 捕获** |
| F-05 | 信号发射:在合规频段与功率下发射,可模拟目标信号 | P0 | 受 60-compliance 强制约束 |
| F-06 | 多模块兼容:按用户配置加载 CC1101 / SI4463 等驱动 | P0 | 每模块独立 SPI、独立天线 |
| F-07 | 手机 App 远程控制(Wi-Fi 经路由器) | P0 | |
| F-08 | 手机 App 近距控制(BLE 直连) | P1 | **仅 Android**(C-06);iOS 已放弃 |
| F-09 | DeepSeek 智能分析(类型/协议/威胁等级) | P1 | 在 App 侧调用 |
| F-10 | 依 AI 结论回下发动作指令(发射/保存) | P1 | 发射仍需人工二次确认 |

### 3.1 明确不做(非目标)

- ❌ 不做通用频谱分析仪(无扫频前端/无校准功率测量)
- ❌ 不承诺解调任意未知协议;只做**已知协议指纹 + 通用特征描述**
- ❌ 不做 GSM/LTE/Wi-Fi 数据包解码(2.4GHz 部分仅做能量与 nRF 私有包)
- ❌ 不绕过任何加密或访问控制
- ❌ 不做发射功率的精确标定(仅档位控制)

## 4. 关键约束

| ID | 约束 | 影响 |
|---|---|---|
| C-01 | 主控固定为 ESP32-S3N16R8(16MB Flash / 8MB PSRAM) | 决定可用外设与内存预算 |
| C-02 | 每个射频模块独占 SPI 与天线 | 决定引脚预算与共存干扰模型 |
| C-03 | 必须免焊接(模块直插/排针) | 决定 BOM 与载板形态 |
| C-04 | 发射必须合规(频段白名单 + 功率上限) | 软件强制,非可选 |
| C-05 | 设备放置远处时无人值守 | 需要看门狗、状态恢复、超时保护 |
| **C-06** | **App 仅支持 Android**(2026-09-20 决策) | 删除 iOS 全部约束;可要求 HTTPS/`wss`、可依赖 Web Bluetooth、PWA 或原生 Android 均可 |
| **C-07** | **设备端必须具备 OLED 显示屏**(2026-09-20 决策) | 首次配对的一次性码显示载体;也是无手机时的本地状态出口 |

## 5. 成功判据(实现阶段验收)

| ID | 判据 | 证据形式 |
|---|---|---|
| A-01 | 手机 App 可在 30s 内连上设备(Wi-Fi 或 BLE) | 真机日志 + 录屏 |
| A-02 | 扫频结果与商用频谱仪/已知遥控器实测频点一致(±100kHz 内) | 对比表 |
| A-03 | 成功捕获并复现一路 433.92MHz OOK 遥控器信号,接收端响应。**必须用 M1(SI4463)完成**——M2/M3 不支持 OOK,见 §6.2 | 现场演示 |
| A-04 | App 提交特征给 DeepSeek 后返回结构化分析结果 | 接口响应样例 |
| A-05 | 越界频段/超功率的发射请求被设备拒绝并记录审计 | 负向测试用例 |

## 6. 硬件选型(需求给定)

### 6.1 主控

**ESP32-S3N16R8** — Xtensa LX7 双核 240MHz,16MB Flash,8MB PSRAM,集成 2.4GHz Wi-Fi + BLE。

### 6.2 射频模块

| 编号 | 型号 | 芯片 | 频段 | 功率 | 接口/尺寸 | 特点 | 调制能力 |
|---|---|---|---|---|---|---|---|
| M1 | AS10-M4463D-SMA | Silicon Labs SI4463 | **425–525MHz**(官方手册,软件可调) | **100mW / 20dBm** | 4-Pin 硬件 SPI,24×16mm 直插 | 工业级,绕射及穿墙能力强,官方标称距离 2km;灵敏度 −126dBm@1kbps | **OOK/ASK + FSK 族**(SI4463 支持)⇒ **433MHz OOK 遥控器靠它** |
| M2 | AS07-M1101D-SMA | TI CC1101 | **387–464MHz**(官方手册,推荐 433±10MHz) | **10mW / 10dBm** | DIP 直插,28×15mm | 自带 FEC 与交织编码,抗干扰强,功耗低;灵敏度 −111dBm@1.2kbps | ⚠️ **官方手册只列 2-FSK / GFSK / MSK,无 OOK/ASK**(芯片本身支持 OOK,是模块未承诺) |
| M3 | AS01-ML01(**已确认,无后缀**) | Nordic nRF24L01P + **RFX2401C PA/LNA** | 2400–2525MHz(126 信道) | **约 20dBm / 100mW**(官方手册) | SPI,18×33.3mm 直插,SMA-K | 内建 LNA,6 通道数据;官方标称距离 2.0km;**带金属屏蔽罩** | GFSK |

> **制造商已确认**:三块均为**泽耀科技 / Ashining**(`ashining.com.cn`)。官方资料包已于 2026-09-20 完整取得,上表**全部为官方手册口径**;明细与"仍开放项"见 [`040-verified-platform-facts.md`](040-verified-platform-facts.md) F-4/F-4c。
>
> ⚠️ **M1/M2 的频段是模块级、不是芯片级**:SI4463 芯片可达 142–1050MHz、CC1101 芯片有三段,**但这两块模块的前端把能力裁掉了**。要覆盖更宽必须换/定制模块,不是换芯片版本。

> ⚠️ **一条会改变功能归属的硬约束**:M2(AS07-M1101D)的**官方模块手册**调制栏只列 **2-FSK / GFSK / MSK**,通篇无 ASK/OOK;其官方原文另称 2-FSK"与使用 ASK(AM)的简单遥控器不兼容"。而 M3(nRF24L01P)在 2.4GHz、与 433MHz OOK 无关。**因此 433MHz OOK 遥控器/传感器的捕获与复现,只能由 M1(SI4463)承担。** 这对 A-03 与需求 F-02 的实现路径有直接影响:OOK 相关的测试与验收必须绑定 M1,不能"随便用哪个模块"。
>
> **层级说明(避免误读为物理限制)**:随模块资料包取得的 **TI CC1101 数据手册明确支持 "OOK and flexible ASK shaping"**。所以这是**模块级官方口径的缺口**(厂商未列出/未承诺),不是"CC1101 芯片做不到"。若日后需要 AS07 做 OOK,须先向厂商确认固件/寄存器是否放开。

> ⚠️ 覆盖空白:该三模块无法覆盖 119–1050MHz(**模块级仅约 15%**,官方手册数据),见 [ADR-0001](../adr/0001-frequency-coverage-gap.md)。选型是否调整属用户决策。
